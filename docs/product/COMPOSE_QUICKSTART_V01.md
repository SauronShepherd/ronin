# Ronin v0.1 Docker Compose quickstart

This is the supported local v0.1 container topology. It uses one Ronin image for the HTTP server, durable worker, constrained runner broker and isolated Python cell containers; one named volume for SQLite and execution evidence; and the host Docker socket only in the internal runner-broker service.

## Prerequisites

- Docker Engine with the Compose v2 plugin.
- A local checkout of this repository. Ronin v0.1 does not clone or synchronize repositories for you.
- An explicit local bearer token supplied as `RONIN_TOKEN`. The repository no longer provides a known default token.
- A separate random internal runner-broker token supplied as `RONIN_RUNNER_BROKER_TOKEN`. Do not reuse the public control-plane bearer token for this purpose.

Run all commands from the repository root. Set private local tokens before starting, for example with values generated by your password manager or operating-system credential tooling:

```sh
export RONIN_TOKEN='replace-with-a-private-random-local-token'
export RONIN_RUNNER_BROKER_TOKEN='replace-with-a-different-random-local-token'
```

Do not reuse those example values literally.

## Start

```sh
docker compose up -d
```

Compose fails during interpolation if either required token is missing. On the first successful invocation Compose builds `docker/Dockerfile` as `ronin:local`. The server publishes only to `127.0.0.1:8080`. The runner broker has no published host port. The durable worker waits for both the server and runner-broker healthchecks before starting.

Inspect readiness with:

```sh
docker compose ps
```

The server healthcheck calls the non-versioned, unauthenticated `GET /healthz` operational endpoint. A TCP listener alone is not enough: the server reports ready only when the existing SQLite database is at the current schema version and answers a bounded read. The endpoint returns no schema number, path, credential, job state, or exception text.

The broker has its own internal `/healthz` readiness endpoint. Its execution/runtime routes require the dedicated broker token and are reachable only on the private Compose network in this topology.

Compose retains a 2-second health interval, 3-second outer timeout, 25 retries, and 2-second start period. The probes use bounded HTTP timeouts. The frozen v0.1 requirement remains healthy in under 60 seconds and still requires real Compose timing qualification before it can be claimed.

## Use the bundled CLI

The optional `cli` Compose service uses the same image but receives neither the Docker socket nor the durable data volume. It can validate the mounted checkout and call the server over the private Compose network.

```sh
docker compose run --rm cli ronin doctor --require core
docker compose run --rm cli ronin validate examples/demo
docker compose run --rm cli ronin plan examples/demo -t notebooks/etl.ronin.json
```

Submit the demo and retain the printed Job ID:

```sh
docker compose run --rm cli ronin submit examples/demo -t notebooks/etl.ronin.json --idempotency-key quickstart-v1
```

Then inspect it using the returned ID:

```sh
docker compose run --rm cli ronin status JOB_ID --wait
docker compose run --rm cli ronin logs JOB_ID
docker compose run --rm cli ronin evidence JOB_ID
```

The server-side grant remains deliberately limited to project `examples/demo` and the seven v1 job-control actions. Use a Compose override if you need a different project grant set.

## Topology and security boundary

- `server` has the SQLite volume and no Docker socket.
- `worker` has the same SQLite volume and the checkout read-only at `/workspace`, but **no Docker socket**. It owns durable claim/heartbeat/fencing/checkpoint semantics and delegates only one structured cell execution at a time to the broker.
- `runner-broker` has the durable volume and `/var/run/docker.sock`, but no repository checkout and no published host port. It resolves `RONIN_IMAGE_REF` to an immutable local `sha256:` image ID and constructs Docker commands itself.
- The worker→broker request contains only execution identity plus prepared cell language/source. It cannot select Docker argv, mounts, network mode, capabilities, engine, user or image. The broker reconstructs the hardened `DockerContainerKernelExecutor` configuration locally.
- `cli` has the checkout read-only and no Docker authority.
 - The image runs product processes as UID/GID `65532:65532`. Services that need initial volume/socket preparation start their entrypoint as root only long enough to prepare permissions and then drop privileges with `gosu`.
- The broker-backed worker obtains the broker-reported immutable runtime image and requires that same identity for each execution. Cell containers remain read-only, networkless, capability-dropped, non-root and resource-limited by the existing runner contract.
- Cancellation is explicit: the worker maps kernel cancellation to the broker execution ID, and the broker signals the same thread-safe cancellation token consumed by the Docker executor.
- The dedicated broker token is a service credential for this private topology. Compose declares `RONIN_BIND_POLICY=container-internal` for plaintext HTTP on the private bridge; do not expose the broker port or reuse this private-topology policy for remote plaintext execution.
 - **Broker compromise still carries Docker-host authority.** This architecture reduces authority held by the durable worker and constrains the worker→Docker path; it does not make the Docker socket itself safe or sandbox the broker from the host daemon.
 - The image runs product processes as UID/GID `65532:65532`. Server/worker containers start their entrypoint as root only long enough to prepare volume/socket permissions and then drop privileges with `gosu`.
- The worker resolves `RONIN_IMAGE_REF` through the Docker daemon to an immutable local `sha256:` image ID before constructing the execution runtime. Cell containers remain read-only, networkless, capability-dropped and resource-limited by the existing runner contract.
- Worker artifacts use local content-addressed storage by default. To select the tested S3-compatible artifact adapter, set `RONIN_ARTIFACT_BACKEND=s3`, `RONIN_S3_BUCKET`, and optionally `RONIN_S3_PREFIX`, `RONIN_S3_ENDPOINT_URL`, and `RONIN_S3_REGION`; incomplete or unsupported values fail closed rather than falling back to local storage.
 - The optional read-only SQL endpoint is enabled by setting `RONIN_SQL_PARQUET_ROOT` to an existing directory. The server registers only its immediate `*.parquet` files as relations named after their validated file stems; subdirectories and other file types are not registered.
- Git safe-directory handling is scoped to the mounted `/workspace`; the image does not configure `safe.directory=*`.
- The built-in server is plaintext HTTP only. Compose sets `RONIN_BIND_POLICY=container-internal` for the server and bundled CLI because they communicate over the private Compose bridge using `http://server:8080`.
- `container-internal` is a declaration about this supported topology, not encryption and not a generic remote-HTTP permission. The host port remains bound only to `127.0.0.1`; do not change it to a public interface without placing an external HTTPS/TLS terminator at the client-facing boundary.

See [`HTTP_TRANSPORT_V01.md`](HTTP_TRANSPORT_V01.md) for the complete transport-security contract.

## Stop and clean up

Stop containers while preserving durable data:

```sh
docker compose down
```

Remove the local durable volume as well:

```sh
docker compose down --volumes
```

Do not use `--volumes` if you need to retain Job, Run, Attempt, artifact or execution-evidence state.
