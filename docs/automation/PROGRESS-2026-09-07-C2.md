# Ronin progress — 2026-09-07 C2 Run-global HTTP events

## Scope

This increment advances handoff #54 with the bounded public event surface immediately after C1 list/cancel. It exposes the already-complete C0 Run-global event semantics through the authenticated job API and `pyronin`; it does not add evidence, D1 operator CLI, Compose, or new authorization semantics.

## Implemented

- Added a storage-neutral `JobStore.get_run_id_for_job()` projection so a public Job can resolve its durable Run without deriving IDs or reaching into SQLite from server code.
- Implemented the projection in the public in-memory and SQLite paged adapters and exposed it through the bounded async store facade.
- Added `DurableExecutionService.events()` which resolves Job -> Run and delegates to the existing C0 bounded `read_event_page()` contract.
- Added authenticated `GET /v1/jobs/{job_id}/events` with bounded `limit`, opaque Run-bound `since`, normalized errors, and fail-closed unknown/repeated query handling.
- Public event payloads preserve dense Run-global `sequence` plus `attempt_id` and `attempt_sequence` provenance, `kind`, `message`, and canonical `Instant` text.
- Extended the OpenAPI 3.1 contract with `JobEvent`, `JobEventPage`, and canonical `Instant` representation.
- Aligned `pyronin` with bounded `JobEventPage` polling instead of the previous unbounded-list placeholder.
- Added SDK parser/validation coverage and a real HTTP + SQLite + `pyronin` integration path spanning replacement Attempts, cursor continuation, attempt provenance, cross-Run cursor rejection, missing jobs, and invalid limits.

## Reuse and boundaries preserved

- C0 remains the single source of truth for event ordering, sequence assignment, keyset cursor construction, cursor Run-binding, and bounded page semantics.
- Canonical durable event identity remains `(attempt_id, sequence)`; the API exposes the existing Run-global projection rather than rewriting storage identity.
- Job and Run IDs remain independent. The server never derives one from the other and does not keep a process-local Job -> Run map.
- Blocking store calls remain behind `BoundedAsyncJobStore`; no synchronous SQLite work was added to the HTTP service loop.
- No Docker, cloud, engine, catalog, format, model-provider, runtime-vendor, or framework types entered the canonical domain.
- #52 was explicitly considered: this increment reuses the existing static bearer-token check and does not define or freeze new scope/grant semantics. #52 remains open before authorization semantics are expanded.
- `/evidence` remains intentionally absent until #53 freezes portable evidence identity.
