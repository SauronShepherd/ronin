# Ronin progress — 2026-09-07 C1 HTTP list/cancel

## Scope

This increment advances handoff #54 with the next bounded HTTP/SDK contract slice after D0. It deliberately implements only job listing and cancellation over the already-qualified durable service/storage contracts. Public events remain for the next #54 increment, and public evidence remains blocked on #53.

## Implemented

- Added `DurableExecutionService.list_jobs()` over the existing bounded async `JobStore` facade.
- Added authenticated `GET /v1/jobs` with stable C0 keyset pagination, bounded `limit`, opaque `cursor`, optional project/state filters, and fail-closed query validation.
- Added authenticated `POST /v1/jobs/{job_id}/cancel` over the existing durable cancellation transition.
- Extended the version-controlled OpenAPI 3.1 contract for list and cancel.
- Aligned `pyronin` job listing with the canonical paged response through `JobPage`, including limit/cursor validation.
- Added SDK and real HTTP + SQLite integration qualification for pagination, cancellation, invalid list requests and missing jobs.

## Boundaries preserved

- Canonical lifecycle/storage semantics remain in `studio_orchestrator`; HTTP maps those contracts and does not define a parallel lifecycle model.
- The server continues to use `DurableExecutionService` and bounded async storage; no blocking `JobStore` call was introduced on the HTTP service loop.
- No Docker, cloud, engine, catalog, format, model-provider or vendor-specific semantics entered canonical packages.
- `/evidence` is intentionally absent until #53 freezes portable evidence identity.
- `/events` is intentionally deferred rather than inventing a second Job-to-Run/event coordinate contract; C0 Run-global event pages remain the storage source of truth.
- Existing acceptance skips and release thresholds are unchanged in this increment. Raw HTTP capability alone is not treated as the supported CLI/operator acceptance journey.

## Planning impact

D0 is complete on main and should no longer be selected. After this increment, the next critical-path slice remains #54: expose bounded Run-global events through the supported job API and continue executable OpenAPI/SDK conformance, with #52 considered before freezing authorization semantics. #53 remains required before public evidence.
