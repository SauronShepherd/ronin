# M2 — prompt in-flight cancellation and cleanup

This increment advances frozen v0.1 acceptance step 14 without changing the 300-second execution timeout or weakening any qualification gate.

## Capability

The durable worker now supervises Job cancellation concurrently with in-flight cell execution. It polls durable Job state at a production default of one second, signals the existing kernel cancellation token as soon as the Job enters `cancelling` or `cancelled`, and cancels/awaits the supervisor task on every worker exit path just like the heartbeat task.

The Docker runner remains the cleanup authority behind the kernel executor boundary. Its existing cancellation path force-removes the deterministic session container; the worker does not depend on the HTTP server and does not gain a Docker-specific orchestration dependency.

## Qualification

A deterministic unit test uses an event-controlled executor and an injected polling wait seam so cancellation is proved while `execute()` is still in flight without wall-clock sleeps.

The frozen real-Docker acceptance journey now runs a deliberately long first cell with the unchanged 300-second executor timeout, waits until that exact container is visible, invokes `ronin cancel` through the authenticated HTTP path, requires the durable Job/Attempt outcome to become `cancelled` within a wide 10-second qualification bound, and requires the exact session-scoped container name to be absent from `docker ps` afterward.

Docker Qualification therefore ratchets the exact skip allowance from `01,12,14` to `01,12`. Strict release remains 15/15 with zero allowances.

## Remaining frozen acceptance gaps

- Step 01 — production image + Compose health.
- Step 12 — public portable evidence endpoint/operator surface after availability semantics are finalized.

No other frozen acceptance step is intentionally skipped by this increment.
