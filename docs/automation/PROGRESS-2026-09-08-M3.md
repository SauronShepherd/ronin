# M3 — public durable evidence

Date: 2026-09-08

This slice implements the finish-plan M3 target only: frozen acceptance step 12 and the public evidence contract. Compose (M4), SQLite structural collapse/coverage-baseline removal (M5), and release hardening (M6+) remain separate work.

## Contract and architecture

- `StoredEvidenceRef` now models `available`, `missing`, `tombstoned`, and `unavailable` explicitly.
- `missing` and `tombstoned` preserve the last trustworthy logical identity; `unavailable` requires a normalized reason and carries no digest, size, or storage locator.
- The active SQLite adapter upgrades its alpha evidence table so digest/size/locator can be null for genuinely unavailable evidence. It does not fabricate placeholder content identity.
- Public evidence is resolved through `DurableExecutionService` using Job -> latest Run -> durable evidence. The worker remains independent of the HTTP server.
- Public payloads deliberately omit the internal `storage_ref`/locator. Storage location is not canonical evidence identity.
- The same v1 representation is exposed through authenticated `GET /v1/jobs/{job_id}/evidence`, `ronin evidence`, OpenAPI, and `pyronin`.
- Existing bearer authorization behavior is reused without expanding or freezing the still-open typed-scope semantics from #52.

## Frozen journey correction

The acceptance text has always required six executed cells, but the demo fixture contained six authored cells with one Markdown cell, so only five reached the worker. M3 converts the stable `intro` cell to executable Python while preserving its provenance anchor/cell ID. The real-Docker crash gate still stops before the fourth Docker execution, so attempt 1 checkpoints exactly three cells and attempt 2 must reuse those exact three and execute cells 4–6.

Step 12 now reads evidence through the real authenticated server and CLI after the crash/reclaim journey, requires exactly six executed cell IDs, and requires both `log` and `resource` portable references for every cell. It also checks the SDK projection and asserts that neither `storage_ref` nor `locator` appears publicly.
