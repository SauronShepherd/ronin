## Carencia productiva y corrección

La auditoría D22 comparó la superficie pública con el dispatcher real. La
OpenAPI y el SDK anunciaban:

```text
GET /v1/workspaces/{workspace_id}/catalog/assets/{asset_id}/revisions
GET /v1/workspaces/{workspace_id}/catalog/assets/{asset_id}/revisions/{version}
```

pero las dos ramas estaban dentro de `do_POST`, de modo que una llamada GET
real terminaba en 404. `91a2d5ef` mueve esas ramas al dispatcher GET y
conserva autorización `workspace.read`, validación de query, 404 de revisión
ausente y serialización de payloads.

También se añadió una prueba de composición local real que arranca el servidor
HTTP y el catálogo SQLite del perfil local, crea dos assets, reemplaza uno,
publica sensibilidad y ownership, lee páginas con cursor, busca, lee las dos
formas de revisión, recorre lineage, comprueba que otro workspace no se filtra,
reinicia y verifica persistencia, y niega una mutación con permisos sólo de
lectura.

La evidencia demuestra aislamiento por workspace. `CatalogAsset.project_id` se
persiste como metadato, pero la superficie pública del catálogo no define un
filtro ni una autorización independiente por proyecto. No se presenta eso como
aislamiento project-scoped: queda abierto para la siguiente revisión de P6.
