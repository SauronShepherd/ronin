## Carencia productiva y corrección

La auditoría de D21 encontró cuatro fronteras de identidad que comprobaban
truthiness pero no el tipo del valor. Un `source_ref`, `subject_ref`, ID de
workflow/schedule/run/task, `BackfillId` o `TaskAttemptId` JSON no textual podía
terminar en `AttributeError` y respuesta 500 en vez de un rechazo de entrada.

El código publicado en `f6674606`:

- valida explícitamente que las identidades del núcleo scheduler sean texto;
- valida `source_ref` y `subject_ref` como texto antes de hacer `strip()`;
- valida `BackfillId` y `TaskAttemptId` como texto antes de normalizarlos;
- añade un journey real local compuesto que arranca la API y el daemon sobre
  SQLite, crea una schedule, observa next-runs, cancela un workflow run,
  entrega un event trigger y ejecuta preview/start/cancel de backfill;
- añade negativos HTTP para referencias no textuales y regresiones focalizadas
  de todas las identidades afectadas.

La prueba local no certifica un worker Docker, PostgreSQL ni un proveedor
externo. Por tanto, esta corrección fortalece P5 pero no la convierte en
`qualified`.
