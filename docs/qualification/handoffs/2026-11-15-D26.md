## Carencias productivas y correcciones

La auditoría de D26 encontró que la celda local de calidad ya podía producir
resultados durables, pero la superficie pública no exponía las operaciones de
alertas y el catálogo/lineage no ofrecía un estado de calidad acotado para el
operador. Catalog Studio tampoco representaba esa señal.

El commit `9ca22d7b` añade al cliente de control-plane y a la CLI las
operaciones `alerts rules`, `alerts instances`, `alerts evaluate` y
`alerts acknowledge`. Añade `include_quality=true` a los recursos de catálogo
y lineage, con resúmenes bounded del último run por asset, y mantiene sin
cambios las respuestas por defecto. Catalog Studio muestra estado `passed`,
`failed`, `error` o `unknown` para assets y extremos de lineage.

La prueba local compuesta usa el servidor HTTP real, SQLite real y telemetría
real: una ejecución pasada no abre alertas; una ejecución fallida abre una
alerta, la evaluación repetida es idempotente y el acknowledge se conserva.
La fuente fallida aparece en catálogo/lineage y un target sin run queda
`unknown`; el replay devuelve el payload fallido idéntico y el contador de
telemetría ejercitado queda en cuatro. Tras reiniciar la composición se
recuperan calidad, historial, alerta y acknowledge. No se usaron mocks para
certificar el proveedor local.
